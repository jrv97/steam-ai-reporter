# AI Reporter for Steam UI design decisions (v1)

The choices behind `tokens.css`, `components.mdx` and `assets/icons/`, with the alternatives weighed, and what is still open. None of these is big enough for an ADR: the plan treats placement rules as tunable constants and copy changes as catalog edits. The published design system carries the same decisions.

## How the values were found

- Computed styles from live store pages on 2026-10-20, logged out, in English. At 1280px: the app page of 5072580, `/search/?term=ai`, a private wishlist URL and the home page. Then the app page of 1808500 for the notice bubbles, tag chips, corner flags and summary box.
- The store's React pages ship their own scale on `:root` (spacing 4 to 32, radii 2, 4, 8, type 11 to 22, control heights 24, 36, 48), which became ours, so injected UI lines up with classic and React pages alike.
- Contrast uses the WCAG 2.x formula, compositing every translucent token over each sampled ground. Results are in the contrast section of `components.mdx`.
- Every page in `previews/` was rendered in Chrome: the compact badge over light, dark, striped, grey, sky and violet art, the list filter in both modes, and Spanish copy up to three times the English length.

## Decisions

1. **Match the store's look, carry no Valve branding.** Sampled neutrals, sizes and radii; "Motiva Sans" by name only. Rejected: using the store's brand assets (listings reject it, and it would look official); a fully foreign look (a seam on every page).
2. **Violet is the accent.** Rejected: teal (too close to the store's blue), amber or gold (collides with the store's own notices and reads as a warning), red or orange (reads as danger).
3. **The mark is a plain label tag holding a spark.** Rejected: a speech bubble with a spark (reads as an AI chat tool), the letters "AI" (unreadable at 16px, needs translating), an eye or magnifier (surveillance). The tag has no punched hole; its pointed end already says "tag".
4. **The compact badge sits top right on a solid surface.** The store's flags and live pill own the top-left and prices own the bottom edge. Rejected: a translucent or blurred surface (contrast depends on the art; blur is costly on carousels), bottom-left (where cover art puts the game's logo).
5. **Compact tiers are measured in script, not with container queries.** `container-type` would change how store containers size themselves.
6. **On search rows the full badge goes on the line under the title.** The title line clips.
7. **The banner sits above the purchase box, in a shadow root.** Rejected: the right column (326px wide, below the fold), under "About this game" (after the buying decision), a modal (what people asked to get away from), light DOM (store CSS styles bare `h2`, `p`, `button`).
8. **The banner attributes every word to the developer.** Nothing paraphrases or rates the notes.
9. **"Stop marking this game", not "Ignore this game".** The store's own Ignore sits just above. The allow-list is "Games you stopped marking" with "Mark again".
10. **The list filter reads Show, Dim, Hide.** "Games that disclose AI use: Off" could read as turning the games off.
11. **Dim is opacity 0.4 only.** Rejected: grayscale (an effect layer per capsule, hundreds on a sale page).
12. **Settings are attributes on the root element; the list filter is pure CSS.** Rejected: toggling classes per host (one write per capsule, re-applied on every React re-render), inline styles (same cost, and they fight the store's).
13. **The banner collapses at 3 lines, without animation, and forgets the expanded state.**
14. **Replaced by decision 32.** The compact badge still takes the pointer only inside the capsule link.
15. **Settings pages are dark only, in a system font.** A light theme would need a second palette for no v1 gain.
16. **The 128px icon carries 16px of transparent padding** (Chrome Web Store guidance); 16, 32 and 48px are full bleed, and 16px is hand-hinted.
17. **Tokens live on the store page's `:root`, all prefixed `sar-`.** Shadow roots inherit them.
18. **Every message is a catalog key** with a translator note. Labels that quote another label take it as a placeholder.
19. **Badges truncate; everything else wraps.** Rejected: shrinking type for long translations (unreadable at 11px), two-line badges (break the row rhythm, cover more art).
20. **Compact tiers depend on image size only,** so a capsule looks the same in every language.
21. **Logical properties and logical token names.** The switch thumb's `translateX` is the one physical value.
22. **A language picker on the full options page,** naming each language in itself through `Intl.DisplayNames`.
23. **The name is AI Reporter for Steam** (short name AI Reporter; repo slug `steam-ai-reporter`). Our name comes first and "for Steam" says only what it works with, so it does not read as an official Steam product; the same pattern as the prior-art extensions credited below. Rejected: Steam AI Reporter, which leads with the trademark.
24. **The prefix is `sar-`,** from the repo slug `steam-ai-reporter`, replacing the working name's `sfs-` before any code ships. Every class, attribute and custom property uses it.
25. **The banner is a store notice bubble in our hue.** Modeled on the DLC notice (`game_area_bubble`), sampled on 2026-10-20: a 135 degree wash at 80% from 10% to 100%, no border, radius or shadow, 8px 16px 12px padding, light Motiva type in `#d5d6d8`, the store's white-transparent button and underlined in-bubble links. Ours swaps the DLC plum for accent 800 to accent 600, keeps a 16px gap below (not 2px) so it never reads as part of the offer, sets the notes italic like the store's own disclosure section, and lifts the button edge to 50% white and the link color to `#d5d6d8` to stay AA. The allow-listed note takes the DRM notice's geometry in neutral. Rejected: the first draft's card (a colored rule on one edge, 4px radius, drop shadow), which is generic callout chrome the store never uses; a neutral surface, which would pass as the store's own content; the DRM notice (one line, no room for notes or actions), the coming-soon and purchase boxes (rounded with shadows), the Early Access header (bordered), and the orange notice box (the store's warning tone, which judges).
26. **The full badge is a store tag chip in our hue.** Modeled on `.app_tag`: 19px tall, 7px padding, 2px radius, no border, a 20% tint. Text is accent 200 on accent 400 at 20%. It keeps the page font instead of the chips' Arial because it sits in Motiva rows. It carries no icon (decision 30); the violet hue and the wording set it apart from the store's blue tags, and it never sits in the store's tag row.
27. **The compact badge mirrors the store's corner flags.** Modeled on `.ds_flag`: 5px from the top, flush to the edge, 19px tall, square, solid. Ours sits at inline-end with accent 100 on accent 900, plus a 1px accent 400 edge and an outer ring. Rejected: a mid-tone flag color (accent 700), which left mid grey art with no boundary at 3:1 (surface 2.54, edge 1.11) and violet art at 2.01.
28. **Backups are a file the person keeps.** Download a JSON file; restore it after a check that shows its date and contents. Restore replaces settings and merges the game lists, so nothing on the current browser is lost. Full options page and userscript dialog only. Rejected: browser sync storage (stays within one browser family, needs a browser account, and its small quota cannot hold the lookup history); an account or server copy (the product sends nothing anywhere); a paste-in text box (clumsy for a large history); restoring the moment a file is picked (no chance to catch the wrong file). The check's Restore and Cancel row sits on the right with Restore first, like the store's own confirm dialogs.
29. **A summary-box row under Publisher, not a chip in the tag row.** The summary box at the top right is above the fold, while the banner usually is not. Steam's own reviews row there is a link that jumps to the reviews section, so a row whose violet chip jumps to our banner is a native pattern. Sampled on 2026-10-20: rows are flex label and value pairs in Arial 13/18, labels 35% wide, 11px uppercase. Rejected: first chip in the tag row (the row never wraps and Steam's own script hides tags that do not fit, so ours would overflow or force us to hide a store tag; it would also sit under "Popular user-defined tags" and read as a player tag); a floating bubble (covers content, against "never block"). The wording "AI use: Disclosed by the developer" (`summary_label`, `summary_value`) was approved on 2026-10-20.
30. **No icons in labels or the banner.** Badges, the summary row chip and the banner carry no spark; only the extension icon keeps it. The store's own tags, corner flags and notice bubbles carry no icons either, and the violet hue plus the wording still mark our UI. Images under 180px wide get no compact badge, since that tier showed only the spark. Rejected: keeping the spark (the user preferred labels without it, 2026-10-20); a short "AI" flag on small images (new copy, and a bare "AI" reads as a verdict rather than a disclosure); squeezing the full label onto small images (it truncates to something like "AI dis...").
31. **The popup is flat and compact.** The toolbar popup shows its sections as flat groups split by a divider, captioned in small uppercase like the store's own section labels, with 4px rows and the store's 24px control height for the segmented control. An empty allow-list is left out there; the full page keeps its empty state. The full page keeps its cards, with 12px padding, 8px apart. Rejected: the same cards in the popup (padding and an empty card took most of its height); dropping the captions (the rows would lose their grouping).
32. **The badges' tooltip is a hover card built like the store's game hover popup.** One panel per page, sampled from `#global_hover` on 2026-10-21: `#344352`, the store's 20px shadow, 16px padding, 306px wide, square. It quotes the developer's notes verbatim, clamped to 6 lines, and names the AI service. Only the violet title marks it as ours. It sits 8px under the badge at z-index 2100, above the store's popup (1526), and it opens as a manual popover so it also clears the React hover layer, which sits in the browser's top layer, and a compact badge hangs it back over the capsule, away from where the store's popup opens. The summary row opens it only while the banner is off, and on the game's own page it drops the line that points to the store page. Rejected: the native `title` (cut at 200 characters, unstyled, delayed by the browser, and invisible to keyboard users); a custom tooltip without the store's surface (a seam next to the store's own popup); the store's arrow (ours sits right under its trigger); a violet accent edge (decision 30 removed edge chrome, and the violet title already marks it).

## Ideas credited

Nothing was copied from prior-art extensions. Ideas that shaped this, to credit in the project README: a dismissible banner in the style of the store's DRM notice instead of a modal (requested in Augmented Steam issue 1913, shipped by Obvious Steam AI); dim or hide modes for lists (AI warning for Steam); falling back from hiding to highlighting where a list cannot hide (AI Generated Content Filter for Steam); a row of our own in the summary box (SteamDB's browser extension adds its rating row there).

## Open questions

1. **"Stop marking" or "Ignore".** Keep decision 9, or return to the plan's "ignore this game" and accept the clash with the store's button?
2. **Wishlist anchor.** The wishlist is React and the sampled one was private; the full badge's exact anchor is unverified.
3. **Row hover color.** `#2a475e` is assumed. The badge passes on it (5.21:1), but confirm the live value.
4. **CSP for styles.** The banner and dialog use `adoptedStyleSheets`; badges rely on the content stylesheet or `GM_addStyle`. If the store's CSP blocks either, fall back to light DOM plus the badge reset.
5. **Line clamp with `pre-line` in Firefox.** Unchecked with notes that contain blank lines.
6. **Forced colors.** The rules are written but unchecked in Windows high contrast mode.
7. **"Steam" in the name and description.** "AI Reporter for Steam" and `ext_description` use the trademark descriptively; check both against the listing policies.
8. **Language of the quoted notes.** The API does not say which language the developer wrote in, so the quote carries no `lang`.
9. **Dim distinctness.** 0.4 against the store's 0.3 is a small difference. If people confuse the two, profile a cheap second cue (a tinted outline on the host) on a sale page first.
10. **Banner next to the DLC bubble.** A game with DLC can carry a disclosure too, so our banner may stack with the store's plum DLC bubble. Compare the two side by side on such a page.
11. **Compact badge and the store's flags.** Both now share the 5px row. On a small capsule a long translation of our label can reach a store flag at the other corner. Measure the widest flag and cap our label if needed.
12. **Banner button hover.** The 10% white hover wash is ours; the store's white-transparent hover state was not sampled.
13. **Restore: merge or replace.** Restore merges game lists by default. Decide whether to also offer "replace everything", for someone who wants this browser to match the backup exactly.
14. **History in backups.** Lookup history is the bulk of the file and refreshes itself anyway. Decide whether it stays in, becomes optional, and how large a file to accept.
15. **Summary row over background art.** The summary box sits on transparent layers: a column gradient (to the right, from 0 to 40% black) and the page's glow, over the game's background art when the page has some. Contrast here is measured on the plain page color. On a page with custom art, measure the label and chip against the lightest pixel behind the box.
16. **Summary row in the narrow layout.** The store's responsive layout moves the summary box. Confirm the row still lands under Publisher there.
17. **Summary row on a tall summary box.** A game with two review rows and a publisher name that wraps adds about 36px; the tag row would hang past the media's bottom edge. Check one such page; if it overflows, drop the row there.
