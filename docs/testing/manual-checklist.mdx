# Manual test checklist

Run before each release, after `mise run canary` passes. Automated tests cover the parsers, the scanner and the placements against captured fixtures; this list covers what only a real browser and a live store show.

## Setup

Targets, each tested logged out and logged in:

| Target                    | How to load it                                                                                                                                            |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Chrome extension          | `mise run build`, then `chrome://extensions`, Developer mode, "Load unpacked", pick `dist/chrome`. Or `mise run run-chrome`.                              |
| Firefox Nightly extension | `mise run run-firefox`, which uses `SAR_FIREFOX_BIN` and the dedicated profile in `SAR_FIREFOX_PROFILE`. Firefox Nightly only: never the regular Firefox. |
| Tampermonkey              | Install `steam-ai-reporter.user.js` from `artifacts/` (or `dist/userscript/`) in Chrome and in Firefox Nightly.                                           |
| Violentmonkey             | Same file, in Chrome and in Firefox Nightly.                                                                                                              |

Before starting:

- Sign in to Steam in the dedicated Nightly profile and in Chrome for the logged-in column; use a private window or a clean profile for the logged-out column.
- Have one wishlist with at least 30 items, including at least one disclosing item (a disclosing app known to work on the day: 5072580 or 1808500; a non-disclosing one: 413150).
- Open the page console on every store page and keep it open. Any error from `sar-` code fails the cell.
- Enable the `debug` setting once to confirm the verbose log appears, then turn it off.

## How to read a cell

A surface cell passes when all of these hold:

1. A disclosing item shows the badge "Discloses AI use"; a non-disclosing item shows nothing; no item shows an "AI-free" or "uses AI" wording.
2. The badge sits on the capsule (not on the page section around it) and does not break the layout.
3. Content added later (infinite scroll, carousel, React re-render, tab switch) gets badges without a reload and without duplicates.
4. The Network tab shows no request to any host other than `api.steampowered.com` and `store.steampowered.com`, no cookies sent on them, and one GetItems call per batch of up to 50 new IDs.
5. Reloading the page issues no new GetItems call for IDs already checked (the cache works).

Mark each cell with P (pass), F (fail, with a note and an issue), or N/A.

## Extra checks

| Check                                                                                                                                                    | Pass |
| -------------------------------------------------------------------------------------------------------------------------------------------------------- | ---- |
| Disabling the extension or userscript removes every `sar-` node on reload                                                                                |      |
| Settings and the allow-list survive a browser restart; clearing storage resets them                                                                      |      |
| Offline or blocked `api.steampowered.com`: no badges, no console error storm, items stay unknown; the app page fallback fetches no more than a few pages |      |
| Firefox Nightly: the content script's GetItems call is accepted by Steam (no CORS failure in the console)                                                |      |
| Userscript: Violentmonkey runs it with its default injection mode; no `@inject-into` change is needed                                                    |      |
| Userscript: the update URL serves the `.meta.js` of the latest release (after the first release only)                                                    |      |
| The dev injection bundle (`dist/dev/inject.js`) is not in any artifact: `mise run package` passes `check_bundle.py`                                      |      |

## Failures

A failing cell either becomes a fixture and gets fixed, or is listed as a known gap in the README. Use `mise run capture-fixtures` for the public pages; capture logged-in surfaces by hand and strip account data as described in `tests/fixtures/README.md`.
