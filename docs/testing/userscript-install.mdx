# Installing the userscript for testing

The userscript is `dist/userscript/steam-ai-reporter.user.js`, written by `mise run build`. A userscript manager runs it on every `https://store.steampowered.com/*` page. Test in Chrome and in Firefox Nightly only; the regular Firefox is personal and stays untouched.

Run `mise run build` first. The file lives in your clone, for example `C:\path\to\steam-ai-reporter\dist\userscript\steam-ai-reporter.user.js`.

## Tampermonkey

1. Install Tampermonkey in Chrome (Chrome Web Store) or in Firefox Nightly (addons.mozilla.org).
2. Chrome only: open `chrome://extensions`, click Details on Tampermonkey, turn on "Allow access to file URLs". Also turn on "Allow User Scripts" if Chrome shows that switch.
3. Open the built file in a tab by its `file:///` address, for example `file:///C:/path/to/steam-ai-reporter/dist/userscript/steam-ai-reporter.user.js`.
4. Tampermonkey shows an install page. Check that the name is "AI Reporter for Steam" (the script name from the first release) and that the permissions list only storage access and a menu command (no network access to other sites). Click Install.
5. To update after a rebuild, open the same `file:///` address again and click Reinstall.

## Violentmonkey

1. Install Violentmonkey in Chrome (Chrome Web Store) or in Firefox Nightly (addons.mozilla.org).
2. Chrome only: open `chrome://extensions`, click Details on Violentmonkey, turn on "Allow access to file URLs".
3. Open the built file by its `file:///` address in a tab, as above.
4. Violentmonkey shows "Confirm installation". Tick "Track local file" so it reloads the script from disk while that tab stays open, then click Confirm.
5. After a rebuild, switch to that tab and reload it; Violentmonkey picks up the new file.

Use only one manager at a time on a given browser, or disable the other one for the test, so the script runs once.

## What you should see

Open each page logged out first, then logged in. The first page load after installing may need a refresh.

1. App page `https://store.steampowered.com/app/5072580/` (Courage and Faith: Into the Dark Woods, reports AI use): a purple banner above the purchase box titled "AI use reported", quoting the developer's text, and an "AI use reported" chip under the Developer and Publisher values.
2. App page `https://store.steampowered.com/app/413150/` (Stardew Valley, no report): nothing added.
3. Search page `https://store.steampowered.com/search/?term=roguelike`: an "AI use reported" badge before the platform icons on the rows whose developers reported AI use (about ten of the first fifty at the time of writing), and nothing on the other rows.
4. Settings: click the manager's toolbar icon, then "AI Reporter for Steam", then "Settings". A dialog titled "Tag Kit for Steam" opens with switches for badges and banner, a Show, Dim or Hide choice, and a list of games you ignored. Escape or Close closes it and returns focus to the page. Change "Games that report AI use" to Hide on the search page: the badged rows vanish at once.
5. Disable the script in the manager and reload: every added element is gone.

## Reporting back

Per manager and browser, note which of the five checks passed, and for each failure the text of the first red line in the page console (F12, Console tab, filter on `[sar]`). Tampermonkey was verified before this build (plain `fetch`, storage, styles); Violentmonkey has not been run yet, so its first run is the real test.

## Renaming the userscript

The script keeps the `@name` of its first release: "AI Reporter for Steam" in English and "Marcador de IA para Steam" in Spanish, both held under `userscript_name` in `src/locales/<locale>/userscript.json`, a catalog that only the userscript header reads. Script managers tell installed scripts apart by name and namespace, so a renamed `@name` may install as a second script beside the old one and leave the stored settings and ignored games with the old copy. Run a spike in Tampermonkey and in Violentmonkey, in Chrome and in Firefox Nightly, before flipping:

1. Install the current build and change a setting, for example ignore one game.
2. Build with a different `@name` and update the way users do (the update URL, or reinstall from the file).
3. Note whether the manager updates in place, installs a second script or asks, and whether the setting survived.

Flip once both managers behave:

1. In `scripts/build.py`, set `USERSCRIPT_NAME` to `("messages.json", "ext_name")`. The `@name` and `@name:es` lines then follow the product name.
2. Delete `src/locales/en/userscript.json` and `src/locales/es/userscript.json`.
3. Update every spot that names the script. In this file: the name check in step 4 of the Tampermonkey list and step 4 of "What you should see". In `docs/store/listing.mdx`: the sentence about `@name` in the first paragraph. In `docs/design/components.mdx`: the `userscript_name` row of the message table.
4. Add a changie fragment (`mise run change-new`). If the spike showed a second script, say that the old copy needs removing and how to carry the settings over, using the backup on the settings dialog.
