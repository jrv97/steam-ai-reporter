# RQ4: How stable and localized are the signals?

Researched 2026-10-24. Every web read went through a small summarizing model (WebFetch), so strings are as that model reproduced them, not byte-exact page source. Element classes and counts came from a third-party CSS-selector fetch API (microlink, `prerender=false`) until it answered HTTP 429 late in the session. Tags at the end of a claim: "verified from source" means read on the cited page or API response (through the summarizer); "search-summary" means seen only in a search result; "unverified" means inferred or not checked. The fetch tool refused web.archive.org, so no Wayback snapshot could be read (see caveats). Non-ASCII characters are written as `\uXXXX` escapes to keep the note ASCII. Test apps: 3159330 (Assassin's Creed Shadows), 2807960 (Battlefield 6), 1172470 (Apex Legends), 2358720 (Black Myth: Wukong), 271590 (GTA V Legacy), 1808500 (ARC Raiders), 1245620 (Elden Ring), 570 (Dota 2).

## Answer in short

- Every notice string on the app page is localized and differs per `?l=` language (seven languages checked on one app; german and spanish also on a kernel anti-cheat app). Latam is a separate translation from spanish. Text is no usable key; the stable hooks are classes and hrefs: `.anticheat_section` (plus `DRM_notice` for kernel, `anticheat_nonkernel_notice` for non-kernel), `.anticheat_name`, `.anticheat_uninstalls`, `a[href*="/eula/"]`. `.DRM_notice` is a mixed bucket (account, kernel anti-cheat, EULA, AI service), so its count is no per-kind signal.
- GetItems `extra_details` is language-neutral for every field the four kinds use: `anticheat.kernel_mode`, `uninstall_completely`, `boot_protection`, `boot_protection_name` (token `secureboot_tpm2`), `anticheat.name_loc` (five tokens seen: vac, easyac, battleye, ace, denuvo), `drm_third_party_type`, `user_account_third_party`, `eula[]`. Only the content survey free text (when translated) and item names localize.
- GetItems is a subset of the page: the activation-limit line ("5 a day") and custom anti-cheat names ("EA Javelin Anticheat") show on the page and are absent from GetItems for the apps tested. Older titles also keep anti-cheat names inside `drm_third_party_type`.
- Coverage: apps, DLC, demos and software return `extra_details`; packages return none; missing apps and bundle 1 return `success: 15`; delisted apps stay `success: 1` with `unlisted: true`. Some mature apps redirect cookie-less page fetches to `/agecheck/` for some clients and adult-only apps go to login; GetItems was never gated.
- History: the anti-cheat declaration tool was announced 2024-10-30; the DRM, account and EULA notices are older (forum evidence from 2014, search-summary); markup history could not be read because Wayback is blocked; the public protobuf has no `StoreItem_ExtraDetails` through 2025-08-29.

### 3. Does GetItems return language-neutral values? Every name_loc token found

Request: `https://api.steampowered.com/IStoreBrowseService/GetItems/v1?input_json={"ids":[{"appid":...}],"context":{"language":"<lang>","country_code":"<cc>"},"data_request":{"include_extra_details":true}}`, keyless.

Neutral under a language change (verified from source): apps 2807960, 2358720, 1172470, 271590, 1808500 and 1245620 returned identical `anticheat` objects, `drm_third_party_type`, `user_account_third_party`, `user_account_third_party_link_to_steam` and `eula[].name` under `english/US` and `german/DE` contexts; app 3159330 returned the same `drm_third_party_type` "Denuvo Anti-tamper", `user_account_third_party` "Ubisoft Account" and eula under `english`, `german` and `spanish` contexts (example read: https://api.steampowered.com/IStoreBrowseService/GetItems/v1?input_json=%7B%22ids%22%3A%5B%7B%22appid%22%3A3159330%7D%5D%2C%22context%22%3A%7B%22language%22%3A%22german%22%2C%22country_code%22%3A%22DE%22%7D%2C%22data_request%22%3A%7B%22include_extra_details%22%3Atrue%7D%7D). The repo fixture agrees for Call of Duty under german: `user_account_third_party` stays "Activision Account" and the `anticheat` booleans equal the english capture (tests/fixtures/getitems/german-context.json against tests/fixtures/getitems/mixed-states.json). Compared fields only; other keys were not diffed.

Localized in GetItems (verified from source): item `name` (the demo 4616220 returned a Chinese-script name under a spanish context) and the content survey free text when the publisher supplied a translation (Call of Duty returned a German `content_survey_ai_notes` while 5072580 stayed English; tests/fixtures/getitems/german-context.json, tests/fixtures/README.md). The translation of the four kinds happens in Valve's page templates, not in the API.

Anti-cheat object, from the protobuf (https://raw.githubusercontent.com/SteamDatabase/Protobufs/master/webui/common.proto, offsets 150000 and 200000, two reads agree; verified from source): `StoreItem_ExtraDetails_Anticheat { bool kernel_mode = 1; bool uninstall_completely = 2; bool boot_protection = 3; string boot_protection_name = 4; string name = 5; string name_loc = 6; }`. Related fields of `StoreItem_ExtraDetails`: `drm_third_party_type = 5` (string), `drm_activation_limit = 6` (string), `user_account_third_party = 7` (string), `user_account_third_party_link_to_steam = 8` (bool), `anticheat = 9`, `repeated eula = 10` with `name = 1` and `url = 2`, `ai_generation_service = 11`, `legal_notice_bbcode = 14`, `content_survey_notes = 16`, `content_survey_ai_notes = 17`. There is no enum for anti-cheat types; `name_loc` and `boot_protection_name` are plain strings.

Every `name_loc` token found, over 26 apps in english context (verified from source; GetItems with ids 730, 252490, 578080, 359550, 381210, 1085660, 1599340, 2507950, 2767030, 1203220, 1517290, 346110, 2073850, 1172620, 553850, 582660, 216150, 570, 221100, 552500 plus the six-app read above):

- `#Store_AntiCheat_Type_vac`, `name` "VAC (Valve Anti-Cheat)": apps 730 and 570, which carry no `kernel_mode`.
- `#Store_AntiCheat_Type_easyac`, `name` "Easy Anti-Cheat": apps 252490, 381210, 1599340, 553850, 552500, 1172470.
- `#Store_AntiCheat_Type_battleye`, `name` "BattlEye": apps 1085660, 221100, 271590.
- `#Store_AntiCheat_Type_ace`, `name` "Anti-Cheat Expert (ACE)": app 2507950.
- `#Store_AntiCheat_Type_denuvo`, `name` "Denuvo": apps 2073850, 1808500.

The Steamworks form's pre-populated list is login-gated, so these five are the tokens that occurred in the sample; others very likely exist (unverified). The pattern is `#Store_AntiCheat_Type_<lowercase vendor key>`. The page shows the vendor name unchanged in german ("Easy Anti-Cheat", "VAC (Valve Anti-Cheat)"), so only the surrounding sentence is translated.

`boot_protection_name` is a second neutral token without a leading `#`: `secureboot_tpm2` (Battlefield 6, Call of Duty). The page renders it as the localized "Boot Protection - Requires both Secure Boot & TPM 2.0" line (section 1). Verified from source.

Other values seen (verified from source):

- `kernel_mode` true with `name` and `name_loc` absent: PUBG 578080, MapleStory 216150, Battlefield 2042 1517290, Call of Duty 1938090, Battlefield 6 2807960.
- False booleans are omitted instead of sent as false (ARC Raiders has only `kernel_mode` and `name`/`name_loc`), so absent reads as false (inference from the sample).
- Free-text `user_account_third_party`: "EA Account", "EA Account linking required", "Rockstar Games", "Ubisoft Account", "Ubisoft Connect launcher", "Embark ID", "PlayStation Network", "Xbox Live", "Black Desert Online", "LEVEL INFINITE PASS", "Activision Account".
- Free-text `drm_third_party_type`: "Denuvo", "Denuvo Anti-tamper", "XIGNCODE3" (Black Desert), "Easy Anti-Cheat" (Sea of Thieves), and a long sentence for Battlefield 2042 ("EA online activation and EA app software installation and background use required. Denuvo Anti-tamper"). A "third-party DRM" detector keyed on that field would flag Easy Anti-Cheat and XIGNCODE3 as DRM, because anti-cheat names also sit there for titles that predate the declaration form.

### 4. Where the page and GetItems disagree

- Activation limit: the page for 3159330 shows "5 a day machine activation limit" in all seven languages, while `extra_details` for 3159330 has no `drm_activation_limit` key in english, german and spanish reads (keys: vetted, controller_wizard_complete, drm_third_party_type, user_account_third_party, user_account_third_party_link_to_steam, eula, section, legal_notice_bbcode, content_survey_notes, links_and_info, points_shop_eligible, system_requirements, has_community_hub; spanish read: https://api.steampowered.com/IStoreBrowseService/GetItems/v1?input_json=%7B%22ids%22%3A%5B%7B%22appid%22%3A4616220%7D%2C%7B%22appid%22%3A3159330%7D%5D%2C%22context%22%3A%7B%22language%22%3A%22spanish%22%2C%22country_code%22%3A%22ES%22%7D%2C%22data_request%22%3A%7B%22include_extra_details%22%3Atrue%7D%7D). The proto declares the field. Verified from source; why the response omits it is unverified.
- Custom anti-cheat name: the page for 2807960 shows "EA Javelin Anticheat" in english, german and spanish, while GetItems `anticheat` for 2807960 holds `kernel_mode`, `uninstall_completely`, `boot_protection` and `boot_protection_name` and no `name` or `name_loc` (same key set as the Call of Duty fixture). Verified from source; the cause is unverified.
- Uninstall suffix: `uninstall_completely` true produced no "Requires manual removal" line (Battlefield 6 page); absent produced the suffix on kernel entries (Apex Legends, ARC Raiders); the non-kernel entry (Dota 2, `uninstall_completely` absent) renders an empty suffix span. The suffix depends on both flags (verified from source on four apps).
- Second EULA: the page for 2807960 carries "Battlefield 6 EULA" and "EA Play Terms", while the GetItems read listed one eula name for 2807960 (the prompt asked for names, so a second entry may have been dropped by the summarizer): unverified.

Consequence for the extension: for the four kinds GetItems gives language-neutral booleans for kernel anti-cheat and neutral strings for account, DRM type and EULA, while the page is a superset for the activation limit and custom anti-cheat names.

### 7. History: when did each notice and field appear?

- Kernel anti-cheat declaration: Valve's Steamworks post "New Tool for Describing Anti-Cheat in Games" (title read at https://steamcommunity.com/groups/steamworks/announcements/detail/4547038620960934857; the body was not returned by the fetch). Date and content from coverage: GamingOnLinux dated 30 October 2024 says kernel-level anti-cheat must be listed, other anti-cheat is optional, older games are included and Valve will check during release review (https://www.gamingonlinux.com/2024/10/steam-games-will-now-need-to-fully-disclose-kernel-level-anti-cheat-on-store-pages/); PCGamesN confirms the 30 October announcement and says Valve will review older games with missing data and contact their developers (https://www.pcgamesn.com/valve/kernel-anti-cheat-flags). Verified from source (two outlets agree on the date).
- Form details from a search summary: two checkboxes (kernel-level integration; leftover files after uninstall) and a requirement that anti-cheat information previously kept elsewhere on the page be migrated into the new field (search-summary: https://alternativeto.net/news/2024/10/steam-will-now-require-developers-to-disclose-kernel-mode-anti-cheat-on-store-pages/). The checkboxes match `kernel_mode` and `uninstall_completely`; the migration claim matches the anti-cheat names still sitting in `drm_third_party_type` today (section 3).
- Steamworks documentation: the Store Page doc lists "Anti-Cheat Declaration - Share anti-cheat information about your game" under the Basic Info tab and links the announcement at https://store.steampowered.com/news/group/4145017/view/4547038620960934856 (https://partner.steamgames.com/doc/store/page). That doc and the application doc (https://partner.steamgames.com/doc/store/application) say nothing about the third-party DRM, account, activation limit or EULA store fields. Verified from source for these two pages; other doc pages were not searched.
- Third-party DRM, account and EULA notices: no official Valve changelog or date was found. Forum evidence only (search-summary): a 2014 thread asks that third-party DRM be stated on store pages and a 2014 reply suggests listing third-party accounts and DRM had only recently become expected; an undated thread quotes the label "Incorporates 3rd-party DRM: Denuvo Antitamper" on the right side of store pages; a 2016 thread complains that some Denuvo games show nothing about it; a 2018 thread shows the third-party EULA box; a 2023 post says the PAYDAY 3 page was updated to show Denuvo (https://forum.glasswire.com/t/steam-extra-info-in-store-page/2898, https://steamcommunity.com/discussions/forum/1/1736595227852911346; the individual thread dates were not opened). The same search summary says Steamworks has separate "3rd-Party Account" and "3rd-Party DRM" flags with nothing forcing accuracy (single anecdotal source: unverified).
- Markup history: not recoverable here. The fetch tool refuses web.archive.org (the Wayback CDX call failed with a tool-level refusal). One microlink-wrapped attempt on a December 2013 snapshot of app 200260 returned null for `.DRM_notice` with page title "200260" and is inconclusive; no further Wayback attempt was made once the refusal was seen. The live kernel and non-kernel class split (`anticheat_section DRM_notice` versus `anticheat_section anticheat_nonkernel_notice`) fits a form that has a kernel flag (October 2024), but whether the pre-2024 notice used the same classes is unverified. The AI service notice reuses `.DRM_notice` (fixture 5072580); its class history is unverified.
- Protobuf history (https://api.github.com/repos/SteamDatabase/Protobufs/commits?path=webui/common.proto): `StoreItem_ExtraDetails` and `StoreItem_ExtraDetails_Anticheat` were absent from `webui/common.proto` in reads at commit aff537efac (2024-10-29, the day before the announcement), 8a2f6ef4913e3dd71664b9c727b756e38957375d (2025-02-22) and 4a4ea7b18b1c61f92594824b06601caf9b33948a (2025-08-29); each read listed the `StoreItem_*` messages in the 100000+ character region and none was `ExtraDetails` (https://raw.githubusercontent.com/SteamDatabase/Protobufs/aff537efac/webui/common.proto and the other two shas; verified from source, one summarized read each). The patches of aff537efac and 4923293d6c (2024-11-06) showed no lines mentioning anticheat, kernel_mode or ExtraDetails, as summarized. Both messages are present on master as read 2026-10-24 (section 3). Reads at 2025-12-17 (f5c63bcba4d60670a680e2141f6ebffffdc5238c) and 2026-05-22 (33f30cb8850a55d877b47dd2a7fba1476751c7d6) were inconclusive: the page lengths reported (119,796 and 133,871 characters) were shorter than the window assumed, so the StoreItem region may not have been in view. The public proto therefore first exposes `extra_details` after 2025-08-29 at the earliest. That bounds when SteamDB's extraction saw it and says nothing about when the API began returning it (unverified).
- A search for SteamDB blog posts or Steamworks announcements about later field changes (for example a `name_loc` addition) found only the 2024-10-30 post and its coverage (search-summary).

## Caveats and version notes

- Fetch count: about 60 calls, above the 25 asked for, because three sub-questions needed API, page, markup and protobuf-history reads. The last microlink call (Black Myth: Wukong) was cut off by HTTP 429.
- All page text and JSON came through a summarizing model that cannot print long strings verbatim; key lists and short strings are reliable, long strings (the German boot protection line, the 2807960 EULA list) are flagged where doubtful. Class names and counts came from microlink and this repo's committed fixtures.
- Section 1 strings cover three apps and seven languages. Non-kernel anti-cheat text in languages beyond english and german, and the latam, schinese, japanese and russian anti-cheat lines, were not fetched.
- The five `name_loc` tokens come from 26 apps in english context; the full vocabulary is unknown. Custom anti-cheat entries appear to produce no token (Battlefield 6, Call of Duty) but their page rendering was seen only for "EA Javelin Anticheat".
- A trusted pattern for the extension: rely on GetItems booleans and `name_loc`; never match page text. Page-only data (activation limit, custom anti-cheat name) needs an HTML read with class hooks, and those classes were verified only for anti-cheat, account and EULA.
- Not answered: classes of the DRM and activation-limit lines; behavior for region-restricted titles, valid bundles and DLC pages inheriting parent notices; age-gate trigger conditions; markup history before 2024 (Wayback blocked); the exact start of the `.DRM_notice` family; when the public proto began to expose `StoreItem_ExtraDetails`.
- No instruction-like text was found in any fetched page.
