# RQ6: Which open-source icon set fits 12 to 16 px chip icons in a no-minify, no-remote-asset browser extension?

Researched 2026-10-24. Facts first; every judgment is labelled "judgment". This note reports licence clauses and does not give legal advice. About 150 fetches were issued, far over the suggested 25, but in parallel batches; most were small registry, GitHub and CDN reads. Fetches went through a small summarising model, which sometimes answered "I cannot check existence" while still showing the file content; an explicit HTTP 404 was treated as "absent", and content shown was treated as "present".

Tag scheme. "verified from source" means read on the set's own registry record, repo, LICENSE or shipped package file. "search-summary" means seen only in a search result. "unverified" means not confirmed. A trailing "(m)" means the fact was read only on the Iconify API (https://api.iconify.design), a third-party mirror that republishes the sets; names read there matched upstream names wherever a second read was possible, but treat "(m)" cells as one level weaker. Byte figures marked "est" were counted by the summariser and are rough.

## Answer in short

- All eleven candidates allow commercial use and none has a copyleft, non-commercial or share-alike clause, but three need a closer look. Remix Icon 4.9.x ships a custom "Remix Icon License v1.0" (January 2026) that forbids selling or distributing the icons as a standalone product and building a competing icon set, while its npm record still says Apache-2.0. Font Awesome Free icons are CC BY 4.0, so attribution is mandatory and its per-icon JS files carry no attribution comment. Lucide is ISC with a second MIT notice for Feather-derived icons (`lock` and `key` are on that list). The rest are MIT or Apache-2.0 (verified from source, section 1).
- Concept coverage (8 concepts): Lucide 8 of 8 (`sparkles`, `shield-alert`, `shield`, `lock`, `user`, `scroll-text`, `swords`, `app-window`); Tabler 8 of 8 but no `scroll`; Phosphor 7 of 8 (only a single `sword`); Heroicons 7 of 8 (no swords); Material Symbols has `swords` but its sparkle icon `auto_awesome` is absent from the SVG package; Font Awesome Free lacks sparkles, swords and a shield with alert (Pro-only); Radix lacks shield, key, cpu and swords.
- Solid variants for every needed icon: only Material Symbols and Phosphor come close (Phosphor's PvP glyph is one sword); Heroicons has a dedicated 16 px solid set but no swords; Tabler fills exist for 6 of 8; Lucide is outline only.
- Bundling: Lucide, Carbon and Font Awesome ship per-icon JS data; Lucide's modules are plain `[tag, attrs]` arrays and its own `createElement` uses `createElementNS` (no `innerHTML`). The others ship SVG files only (needs a text loader or a build-time path extraction). Eight icons cost roughly 2 to 5 KB in every set, so bytes do not separate the candidates; Heroicons is exact at 3,534 B for seven icons.
- Ranking (judgment): 1 Phosphor (fill weight), 2 Lucide, 3 Heroicons (16 solid); Tabler is the first alternate. If the owner accepts an outline look, Lucide becomes first. Details in section 6.

### 2. Style and rendering at 12 to 16 px

Facts per set (grid, weights, variants):

- Lucide: outline only, 24 grid, `stroke-width` 2 in every body, round caps (verified from source: https://cdn.jsdelivr.net/npm/lucide@1.61.0/dist/esm/icons/shield-alert.mjs for the data shape; stroke 2 from https://raw.githubusercontent.com/lucide-icons/lucide/main/icons/swords.svg). The stroke scales with the SVG size, so a 2-unit stroke on 24 draws about 1.33 px at 16 px and 1 px at 12 px (arithmetic). The docs describe `absoluteStrokeWidth` to keep the on-screen stroke fixed; current framework docs rename it `nonScalingStroke` (verified from source: https://v0.lucide.dev/guide/basics/stroke-width; rename seen as search-summary: https://lucide.dev/guide/react/basics/stroke-width). A CSS alternative, `vector-effect: non-scaling-stroke`, was named in the same search result (search-summary). No fill variant exists.
- Tabler: 6,238 icons, 5,184 outline and 1,054 filled, 24 grid, 2 px stroke (verified from source: https://raw.githubusercontent.com/tabler/tabler-icons/main/README.md). Outline files carry `stroke-width` 2 (verified from source: https://cdn.jsdelivr.net/npm/@tabler/icons@3.49.0/icons/outline/swords.svg). Filled files use `fill="currentColor"` and include an invisible 24 by 24 helper path (`fill="none"`), so a filled file has one more element than the glyph needs (verified from source: https://cdn.jsdelivr.net/npm/@tabler/icons@3.49.0/icons/filled/shield.svg and .../filled/sparkles.svg, 2 and 4 path elements).
- Phosphor: six weights, thin, light, regular, bold, fill, duotone (the npm exports map lists bold, fill, thin, light, duotone, regular: https://registry.npmjs.org/@phosphor-icons/core/latest; the 9,072 Iconify entries equal 1,512 icons x 6 weights, arithmetic on https://api.iconify.design/collections?prefixes=ph). Assets live at `/assets/<weight>/<kebab-name>-<weight>.svg` (verified from source: https://raw.githubusercontent.com/phosphor-icons/core/main/README.md; the regular weight has no suffix, as in assets/regular/shield-warning.svg). Every file read had `viewBox` "0 0 256 256", `fill="currentColor"` on the root, one `<path>` and no stroke attributes, even for the regular weight, so weights are baked into outlines and there is no stroke-scaling knob (verified from source: https://cdn.jsdelivr.net/npm/@phosphor-icons/core@2.1.1/assets/regular/shield-warning.svg, .../assets/fill/sparkle-fill.svg, .../assets/fill/sword-fill.svg).
- Heroicons: four sets, 24 outline, 24 solid, 20 solid, 16 solid (verified from source: https://raw.githubusercontent.com/tailwindlabs/heroicons/master/README.md; the README does not use the names "mini" or "micro", those names come from the brief). The 16 solid set is a separate drawing at `viewBox` "0 0 16 16" with `fill="currentColor"` and one path for `sparkles` (verified from source: https://cdn.jsdelivr.net/npm/heroicons@2.2.0/16/solid/sparkles.svg). Each set has 316 icons (verified from source: https://api.github.com/repos/tailwindlabs/heroicons/git/trees/master:optimized/16/solid).
- Material Symbols: variable font axes FILL 0 to 1, wght 100 to 700, GRAD, opsz 20 to 48 dp (verified from source: https://developers.google.com/fonts/docs/material_symbols). The optical size axis starts at 20, above the 12 to 16 px range. The SVG package is weight 400 only, with `outlined`, `rounded` and `sharp` folders and `<name>.svg` plus `<name>-fill.svg` files; the two files read have `viewBox` "0 -960 960 960", width and height 48 and no fill attribute (verified from source: https://cdn.jsdelivr.net/npm/@material-symbols/svg-400@0.48.1/ and the two files fetched under it). Not every icon has a `-fill` file (see section 3, `auto_awesome`).
- Font Awesome Free 7.x solid: single filled style per package (this note read only the solid package). Per-icon canvases are not square: faWandMagicSparkles is 576 by 512, faShieldHalved 512 by 512, and Iconify normalises the set to 640 (verified from source: https://cdn.jsdelivr.net/npm/@fortawesome/free-solid-svg-icons@7.3.1/faWandMagicSparkles.js and https://api.iconify.design/fa7-solid.json).
- Bootstrap Icons: drawn on a 16 by 16 grid (`viewBox` "0 0 16 16", `fill="currentColor"`, one path) and ships outline and `-fill` icons as separate names; `window-fill` does not exist (verified from source: https://cdn.jsdelivr.net/npm/bootstrap-icons@1.13.2/icons/shield-fill-exclamation.svg and https://raw.githubusercontent.com/twbs/icons/main/font/bootstrap-icons.json).
- Iconoir: 24 grid, stroke 1.5, no fill on the root (verified from source: https://cdn.jsdelivr.net/npm/iconoir@7.12.1/icons/regular/shield-alert.svg). A `solid` folder exists, but of 13 candidate names tested only `sparks-solid`, `web-window-solid` and `warning-triangle-solid` exist (m) (https://api.iconify.design/iconoir.json?icons=shield-alert-solid,cpu-solid,lock-solid,key-solid,user-solid,page-solid,shield-solid,app-window-solid,sparks-solid,web-window-solid,warning-triangle-solid,empty-page-solid,cpu-warning-solid).
- Remix Icon: `-line` and `-fill` names for each icon tested, 24 grid (m) (https://api.iconify.design/ri.json?icons=sparkling-fill,sparkling-line,sparkling-2-fill,sparkling-2-line,magic-fill,shield-fill,shield-line,shield-keyhole-fill,shield-flash-fill,shield-check-fill,shield-cross-fill,alert-fill,cpu-fill,cpu-line,lock-fill,lock-line,key-fill,key-2-fill,user-fill,user-line,file-text-fill,file-text-line,file-paper-fill,file-paper-2-fill,article-fill,sword-fill,sword-line,window-fill,window-2-fill,app-store-fill).
- Carbon: the 16 px modules reuse 32 grid artwork (`viewBox` "0 0 32 32", width and height 16) for `security` and `ai-generate`, so no dedicated 16 px redraw was seen for those two (verified from source: https://cdn.jsdelivr.net/npm/@carbon/icons@11.91.0/es/security/16.js and .../es/ai-generate/16.js).
- Radix Icons: 15 by 15 grid by design (verified from source: https://raw.githubusercontent.com/radix-ui/icons/master/README.md), 332 icons (m) (https://api.iconify.design/collection?prefix=radix-icons).

Which sets have a solid or fill version of every icon needed (8 concepts):

- Material Symbols: fill files confirmed for `gpp_maybe` and `swords`; `shield`, `lock`, `key`, `person`, `memory` have fill names on the mirror (m); the sparkle icon is the gap (section 3).
- Phosphor: fill exists for all but the crossed swords, which is absent; `sword-fill` is a single sword.
- Heroicons: solid for all 7 present concepts at 16 px; no swords.
- Tabler: filled exists for sparkles, shield, shield-check, shield-lock, lock, key, user, file-text, app-window (m except shield and sparkles); filled `cpu` and `swords` are 404 in the package, and the mirror shows no `shield-exclamation-filled`. So 6 of 8 concepts have a filled form (verified from source for the two 404s: https://cdn.jsdelivr.net/npm/@tabler/icons@3.49.0/icons/filled/cpu.svg and https://cdn.jsdelivr.net/npm/@tabler/icons@3.49.0/icons/filled/swords.svg).
- Bootstrap: fill for shield, shield-exclamation, cpu, lock, key, person, file-text; no `window-fill`; no sparkle (only `stars` and `magic`) and no swords.
- Remix: fill for every concept it has; no shield-with-alert and only a single `sword`.
- Font Awesome Free solid: everything is solid, but three concepts are missing (section 3).
- Lucide, Carbon, Iconoir, Radix: no fill variant for the needed set.

How each set renders at 12 to 16 px is a visual question; no rendering test was run. Facts that bear on it: Heroicons 16 solid and Bootstrap are drawn at 16 px, Radix at 15 px, Material Symbols' optical size starts at 20 dp, Carbon reuses 32 grid art, and outline sets with a 2-unit stroke on a 24 grid draw 1 to 1.33 px lines. Judgment: solid glyphs hold up at 12 to 16 px better than 2-unit strokes, and solid also matches Steam's own flat glyphs, per the owner's description.

### 4. Consumption under the extension's constraints

Facts about esbuild (the bundler named in the brief):

- Tree shaking is on by default when bundling or when the output format is `iife`; the documentation section does not make it depend on minification (verified from source: https://esbuild.github.io/api/, Tree shaking section). The `sideEffects` field marks files removable when all imports from them are unused (verified from source: same page, Ignore annotations text).
- The default for legal comments is `eof` when bundling (verified from source: https://esbuild.github.io/api/). So a license comment in a source module (Lucide, Carbon) reaches the end of the output file; a set with no header comment (Font Awesome per-icon files, likely Material and Heroicons SVGs) leaves nothing to carry.
- No built-in `.svg` loader exists; the `text` loader is on by default only for `.txt` and exports the file as a string; `dataurl` would produce a Base64 data URL (verified from source: https://esbuild.github.io/content-types/). Importing SVG files therefore needs a loader mapping for `.svg` set to `text` in the build config.

Per set: what the package ships, whether per-icon import tree-shakes, rough size of the eight concept icons, and how to build elements.

- Lucide. Ships JS data. Each icon is a module `dist/esm/icons/<name>.mjs` with a default export that is an array of `[tag, attrs]` pairs (shield-alert: three `path` pairs; app-window: one `rect` plus three `path`; no imports) (verified from source: https://cdn.jsdelivr.net/npm/lucide@1.61.0/dist/esm/icons/shield-alert.mjs and .../app-window.mjs). The package has `sideEffects: false`, `module: dist/esm/lucide.mjs` and no `exports` field, so deep file imports are not blocked by a map (verified from source: https://registry.npmjs.org/lucide/latest; the consequence for deep imports is an inference from the missing field). Module sizes with license header and source map comment: shield-alert about 580 characters, scroll-text 500 to 550, app-window about 440, sparkles about 800 (est). Path data for sparkles, shield-alert, shield, lock, user, scroll-text, swords, app-window sums to about 2,100 characters (est, Iconify bodies: https://api.iconify.design/lucide.json?icons=sparkles,shield-alert,shield,cpu,lock,key,user,scroll-text,swords,app-window). DOM: the package's own `createElement` builds nodes with `document.createElementNS` and `setAttribute`, recursing over `[tag, attrs, children]`, with no `innerHTML` (verified from source: https://cdn.jsdelivr.net/npm/lucide@1.61.0/dist/esm/createElement.mjs). Per-icon import with no minification should work under esbuild's rules above (judgment; no test build was run).
- Tabler. Ships SVG files (`icons/outline`, `icons/filled`) and two JSON dumps of all icon nodes, `tabler-nodes-outline.json` and `tabler-nodes-filled.json`; no `dist/` JS (verified from source: https://cdn.jsdelivr.net/npm/@tabler/icons@3.49.0/). Its exports map is `"./*"` to `./icons/*` and it has `sideEffects: false` (verified from source: https://registry.npmjs.org/@tabler/icons/latest). Files are about 0.5 KB outline (swords about 510 B, shield-exclamation about 550 B, est) and about 0.76 to 0.8 KB filled (shield about 800 B, sparkles about 760 B, est), so eight icons are roughly 4 to 5 KB as files. Whether esbuild drops unused keys from a large JSON import: unverified; do not rely on it.
- Phosphor. Ships SVG files only under `assets/<weight>/`; `dist/` holds metadata (name lists, types). The exports map lists `./<weight>/*.svg` and `./assets/<weight>/*.svg` (verified from source: https://registry.npmjs.org/@phosphor-icons/core/latest and https://cdn.jsdelivr.net/npm/@phosphor-icons/core@2.1.1/). Fill files measured by the summariser: sparkle-fill about 500 B, shield-warning-fill about 380 B, scroll-fill about 600 B, cpu-fill about 700 B, app-window-fill about 281 B, sword-fill about 890 B (est, files under https://cdn.jsdelivr.net/npm/@phosphor-icons/core@2.1.1/assets/fill/). Adding shield-fill, lock-fill and user-fill at an assumed 300 to 350 B each (unverified) puts the eight concept icons near 3.6 KB.
- Heroicons. Ships SVG files only (`16`, `20`, `24` folders, LICENSE, README). Exact bytes of the optimized 16 solid files (GitHub tree API sizes): sparkles 976, shield-exclamation 490, shield-check 514, cpu-chip 726, lock-closed 348, key 409, user 272, document-text 466, window 468, scale 891. For the seven concepts that exist (sparkles, shield-exclamation, shield-check, lock-closed, user, document-text, window) that is 3,534 B; adding cpu-chip gives 4,260 B (verified from source: https://api.github.com/repos/tailwindlabs/heroicons/git/trees/master:optimized/16/solid; folder layout https://cdn.jsdelivr.net/npm/heroicons@2.2.0/). The unoptimized `src/16/solid` copies are larger (sparkles 2,012 B), so use the package copies.
- Material Symbols. Ships SVG files only in the data package (23,595 files in @material-symbols/svg-400); the `material-symbols` package is a font plus CSS (`main` is index.css) and is the wrong shape for this extension (verified from source: https://registry.npmjs.org/@material-symbols/svg-400/latest and https://registry.npmjs.org/material-symbols/latest). Measured files: gpp_maybe-fill about 300 B and swords-fill about 620 B (est). Other bodies on the mirror run 100 to 480 characters (m), so eight icons are roughly 3 KB (est, unverified). Width and height attributes are 48 and must be overridden.
- Font Awesome Free. Ships JS data. Per-icon CommonJS modules `faX.js` export `definition` with `icon: [width, height, aliases, unicode, svgPathData]`; `index.mjs` re-exports all icons for ESM, and the exports map has `"./*"` to `"./*.js"`; `sideEffects: false` (verified from source: https://cdn.jsdelivr.net/npm/@fortawesome/free-solid-svg-icons@7.3.1/faShieldHalved.js and https://registry.npmjs.org/@fortawesome/free-solid-svg-icons/latest). faShieldHalved is about 1,000 characters with about 260 characters of path; faWandMagicSparkles about 1,900 characters (est). Path bodies for ten candidate icons sum to about 5,450 characters (est, https://api.iconify.design/fa7-solid.json?icons=wand-magic-sparkles,triangle-exclamation,shield-halved,microchip,lock,key,user,scroll,file-contract,window-maximize). DOM: read `icon[4]` and create one `path` with `createElementNS`.
- Bootstrap Icons. Ships SVG files, a sprite and fonts; no JS path data (the `types` file only lists font names) (verified from source: https://registry.npmjs.org/bootstrap-icons/latest). shield-fill-exclamation is about 700 B as a file (est). Path bodies for ten candidates sum to about 3,650 characters (est, https://api.iconify.design/bi.json?icons=stars,shield-fill-exclamation,shield-fill,lock-fill,key-fill,person-fill,file-text-fill,window,app-indicator,cpu-fill).
- Iconoir. SVG files only, exports map for `icons/regular/*.svg` and `icons/solid/*.svg` (verified from source: https://registry.npmjs.org/iconoir/latest). shield-alert is about 665 B with 3 paths (est).
- Remix Icon. SVG files and fonts in `remixicon`; a React package exists separately (`@remixicon/react`). File layout inside the package was not read: unverified.
- Carbon. Ships JS data. Per-icon ES modules `es/<name>/<size>.js` default-export a descriptor `{ elem: "svg", attrs, content: [{ elem: "path", attrs: { d } }], name, size }`, with an Apache header and no imports; `sideEffects: false` (verified from source: https://cdn.jsdelivr.net/npm/@carbon/icons@11.91.0/es/security/16.js and https://registry.npmjs.org/@carbon/icons/latest). security/16 is about 1,000 characters (2 paths); ai-generate/16 about 2,000 characters (6 paths) (est).
- Radix Icons. The npm package ships React components (React as a peer dependency, 332 files in dist); standalone SVG files in the package: unverified (verified from source for the React shape: https://registry.npmjs.org/@radix-ui/react-icons/latest).

Turning the data into SVG elements without `innerHTML`:

- For Lucide, Carbon and Font Awesome the data is already structured; a few lines of `createElementNS` and `setAttribute` suffice, and Lucide's `createElement` shows the pattern (verified from source: the createElement.mjs URL above).
- For SVG-only sets (Phosphor, Heroicons, Tabler, Bootstrap, Material, Iconoir, Remix) two routes work: extract the path `d` strings and root attributes at build time into a typed constant and build elements with `createElementNS`; or import the file as text and parse it with `DOMParser` as `image/svg+xml`, then `importNode`. The first avoids a runtime parser and fits the repo's `scripts/` rule; this is judgment.
- Size does not separate the sets: eight icons weigh about 2 to 5 KB in every set that was measured, from the exact 3,534 B Heroicons figure to the roughly 5 KB Font Awesome estimate (judgment from the figures above).

### 5. Where each candidate fails a stated criterion

- Remix Icon: custom licence with standalone-product and competing-library restrictions, and a registry SPDX field that disagrees with the shipped file (section 1). Fails "open source" in the OSI-style sense unless the owner accepts a custom licence; whether the OSI or SPDX list includes it: unverified.
- Font Awesome Free: attribution is mandatory (CC BY 4.0), the per-icon JS carries none, and sparkles, swords and a shield-with-alert are Pro-only or absent (section 3).
- Radix Icons: missing shield, key, cpu, swords; React-only package (sections 3 and 4).
- Carbon: no crossed swords, 32 grid art at every size seen, Apache notice duties.
- Iconoir: no swords, solid forms for few icons, stroke 1.5.
- Bootstrap Icons: no sparkle (`stars` is the nearest), no swords, no filled window.

### 6. Shortlist (judgment)

Ranking against the owner's four criteria (open source, commercially safe, looks good small, cheap to bundle) plus the eight concepts:

1. Phosphor, fill weight. MIT with a one-line notice; flat solid glyphs like Steam's; 7 of 8 concepts exact and PvP as a single sword; one-path SVG files of 0.3 to 0.9 KB; six weights so a hover state or outline form needs no second set; 5 open issues. Costs: SVG-only (build-time path extraction), npm version dates from March 2024 although the repo is active, and no crossed swords.
2. Lucide. Best consumption: per-icon JS arrays, `sideEffects: false`, a DOM builder that avoids `innerHTML`, 8 of 8 concepts including `shield-alert` and `swords`, releases within days. Costs: outline only (1 to 1.33 px lines at 12 to 16 px unless stroke width is raised or non-scaling stroke is used), two licences (add the MIT notice if `lock` or `key` is used).
3. Heroicons 16 solid. MIT; the only set with a dedicated 16 px solid drawing; exact total 3,534 B for seven icons; 4 open issues. Costs: no swords, a small pool of 316 icons if the tagging kinds grow, last npm release November 2024.

First alternate: Tabler (MIT, 6,238 icons, 8 of 8 with `file-text` for EULA, active releases; mixed outline and filled forms, filled `cpu` and `swords` absent). Material Symbols is the only set with a fill form for swords but has the unresolved sparkle gap, Apache duties, and the optical size floor of 20 dp.

What would change the ranking:

- If outline is acceptable on chips: Lucide moves to first.
- If crossed swords for PvP is mandatory in a solid style: Material Symbols (if the sparkle issue resolves) moves up; Tabler outline or Lucide outline are the only other full matches; Phosphor and Heroicons drop.
- If no build-time extraction step is wanted: Lucide, Carbon and Font Awesome move up because their data is JS.
- If the owner wants no attribution duty beyond a notices file: Font Awesome Free drops out; if only MIT or ISC text is acceptable, Material Symbols and Carbon (Apache) fall behind the MIT sets.
- If many more kinds of chip are expected: pool size favours Tabler (6,238), Lucide (1,903) and Phosphor (1,512 icons) over Heroicons (316) and Radix (332).
- If a rendering test at 12 and 16 px shows Lucide with a raised stroke width reads better than Phosphor fill, swap ranks 1 and 2; no such test was run.

## Caveats and version notes

- Dates are single-source (npm registry search endpoint). GitHub "open issues" includes open pull requests. The Carbon and Font Awesome repo counts cover the whole monorepo or project, not only icons.
- Names marked (m) were read on Iconify, which is a third-party mirror of upstream data; the Iconify copy can lag (Remix shows 4.8.0 against npm 4.9.1) or normalise (each set re-based to one viewBox; Tabler's "-filled" names are Iconify's, the package files drop the suffix).
- Byte figures marked "est" were counted by a summarising model and are rough (Phosphor sword-fill came out at about 890 B on a file read and about 450 characters on a body read, so expect +/- 50 percent). The Heroicons figures are exact tree sizes. No test bundle was built, so no figure is a measured esbuild output.
- Lucide is at 1.61.0; the current framework docs rename `absoluteStrokeWidth` to `nonScalingStroke`, so check the installed version before writing config (search-summary: https://lucide.dev/guide/react/basics/stroke-width).
- The Lucide Feather list and the licence summaries came from a summariser reading the raw files; quoted fragments are short on purpose.
- The Heroicons README names four sizes but not "mini" or "micro".
- Leads from the brief: Phosphor MIT with six weights, Heroicons MIT with outline, solid 20 and 16, Material Symbols Apache 2.0 with a fill axis, Font Awesome Free icons CC BY 4.0, Tabler MIT with some filled icons (1,054), Lucide ISC with Feather-derived MIT parts and outline only. All were confirmed above.
- Not answered: which Material Symbols icon replaces `auto_awesome` in the 0.48.1 SVG package; the file layout of the Remix package; whether Radix ships standalone SVG files; whether a plain `shield` exists in Heroicons; real rendering quality at 12 to 16 px; exact byte totals for sets other than Heroicons.
