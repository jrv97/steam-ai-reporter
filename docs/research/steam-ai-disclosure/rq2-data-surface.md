# rq2: how does steam's ai generated content disclosure show up on store pages and in machine-readable data?

## answer in short
- on the app page the disclosure is a server-rendered block `<div id="game_area_content_descriptors" class="game_area_description">` holding `<h2>AI Generated Content Disclosure</h2>`, a fixed lead-in `<p>`, and the developer's free text inside `<p><i>...</i></p>`. the id is duplicated: the mature content description uses the same id and classes, so the only discriminator is the localized h2 text (and document order: ai block came first on the one sample that had both).
- the heading is localized and Valve has edited translations after the fact (Russian 2026-02, French 2026-09), so text matching on a localized page is fragile. every existing tool fetches `?l=english` for detection in lists.
- a no-scrape source exists: `IStoreBrowseService/GetItems` with `data_request.include_extra_details=true` returns `store_items[].extra_details.content_survey_ai_notes` (the same free text as the page) and, for some apps, `extra_details.ai_generation_service` (`name`, `url`). seen working without an api key. `appdetails`, search rows, hover popups, tags and content descriptor ids carry no ai marker.
- there is no steam content descriptor id and no steam store tag for it (descriptor ids seen are 1 to 5 only; the SteamDB "AI Content Disclosed" tag 1368160 is SteamDB's own and absent from Steam's tag list).
- age gates matter: a cookie-less fetch of an app with violence descriptors (Call of Duty, 1938090) was redirected to `/agecheck/app/1938090/`, and an adult-only app redirected to login. treat any response without `id="appHubAppName"` as "unknown", not "no disclosure".

## findings

how the evidence was gathered (read this first): the only fetch tool available converts pages to markdown through a small summarizing model, so raw html was not visible directly. i got server html structure by asking `api.microlink.io` (a third-party fetch api) with `prerender=false` to return css-selected fragments (`data.x.selector`, `attr=html|text|class`), and the helper model then described them. short strings quoted below were returned verbatim by that route; element skeletons are the helper's description of the returned html and are corroborated by the regexes and selectors used in three open source tools (sources below). json fields were read through the same helper, so treat exact numeric values as "seen once". a human with curl or devtools should re-confirm the snippets before hard-coding anything.

### 1. store page html: containing element, selectors, heading, free text

sample with disclosure: app 5072580 (Courage and Faith: Into the Dark Woods), fetched as `https://store.steampowered.com/app/5072580/?l=english` through microlink with `prerender=false` (server html, no javascript run). the left column (`.game_description_column`) listed these direct children in order: `div#game_area_purchase`, `div#bannerCommunity`, `div.purchase_area_spacer`, `div[data-featuretarget="events-row"]`, `div#contentForThisGame_ctn`, `div#aboutThisGame.game_page_autocollapse` (holding `div#game_area_description.game_area_description`), then the ai block, then the mature content block, then `div.game_page_autocollapse.sys_req` (system requirements). (source: https://api.microlink.io/?url=https%3A%2F%2Fstore.steampowered.com%2Fapp%2F5072580%2F%3Fl%3Denglish&meta=false&prerender=false&data.col.selector=.game_description_column&data.col.attr=html)

the ai block, server html skeleton (text shortened, attributes exact as reported):

```
<div class="game_page_autocollapse">
  <div id="game_area_content_descriptors" class="game_area_description">
    <h2>AI Generated Content Disclosure</h2>
    <p>The developers describe how their game uses AI Generated Content like this:</p>
    <p><i>Generative AI is used in both pre-generated and live-generated content. ...</i></p>
  </div>
</div>
```

(source: same microlink route with `data.h.selectorAll=#game_area_content_descriptors > h2` and `data.p.selectorAll=#game_area_content_descriptors > p`, https://api.microlink.io/?url=https%3A%2F%2Fstore.steampowered.com%2Fapp%2F5072580%2F%3Fl%3Denglish&meta=false&prerender=false&data.p.selectorAll=%23game_area_content_descriptors%20%3E%20p&data.p.attr=html&data.h.selectorAll=%23game_area_content_descriptors%20%3E%20h2&data.h.attr=html)

- heading: `<h2>` with no attributes, text exactly `AI Generated Content Disclosure` in english (31 chars). (source: the microlink url above; also the arc raiders check, https://api.microlink.io/?url=https%3A%2F%2Fstore.steampowered.com%2Fapp%2F1808500%2F%3Fl%3Denglish&meta=false&prerender=false&data.h.selectorAll=%23game_area_content_descriptors%20%3E%20h2&data.h.attr=text&data.p.selectorAll=%23game_area_content_descriptors%20%3E%20p&data.p.attr=html&data.name.selector=%23appHubAppName&data.name.attr=text)
- lead-in paragraph: first `<p>`, no attributes, text `The developers describe how their game uses AI Generated Content like this:` (75 chars; identical on app 1808500). the mature content block uses `The developers describe the content like this:`. (source: the two microlink urls above)
- developer free text: the second `<p>`, which wraps an `<i>`. the raw string starts `<i>\n\t\t\t\t\tGenerative AI is used in both pre-generated and live-generated content. AI-assisted tools w...`, so expect leading newline and tabs inside the `<i>`; no `<br>` was present in the three samples (5072580: 465 chars, 1808500: 232 chars). (source: microlink urls above)
- no ids or classes exist on `h2`, `p` or `i`. the usable hooks are `#game_area_content_descriptors`, `.game_area_description`, and the parent `.game_page_autocollapse`. the working selector in a shipped extension is `.game_page_autocollapse > #game_area_content_descriptors > h2`, filtered by heading text. (source: https://raw.githubusercontent.com/seeeeew/aiwarningforsteam/main/aiwarningforsteam.user.js)
- the id is not unique. on 5072580 there are two elements with `id="game_area_content_descriptors"`: the ai block (heading `AI Generated Content Disclosure`) first, the mature block (heading `Mature Content Description`, free text in its own `<p><i>`) second. in a javascript-rendered dom the ai block was reported wrapped as `div.game_page_autocollapse_ctn > div.game_page_autocollapse[style="max-height: none;"]` followed by `div.game_page_autocollapse_fade > div.game_page_autocollapse_readmore` ("READ MORE"). so `querySelector("#game_area_content_descriptors")` returns whichever block is first and can be either one; use `querySelectorAll` and test heading text. (source: https://api.microlink.io/?url=https%3A%2F%2Fstore.steampowered.com%2Fapp%2F5072580%2F%3Fl%3Denglish&meta=false&data.page.selector=html&data.page.attr=html with offset 100000; the Pierre-Demessence banner script takes only the first `h2` of the first block, which would miss the ai block on pages where mature content comes first, see https://raw.githubusercontent.com/Pierre-Demessence/SteamAIGamesIndicator/main/steamAIBanner.user.js, summarized by the fetch helper)
- single-block and zero-block cases: ARC Raiders (1808500) has the ai block and no mature block (appdetails `content_descriptors.ids` is `[]`, `notes` null). Stardew Valley (413150) has no `#game_area_content_descriptors` at all (microlink returned `null` for both `data.h` and `data.cd`). so absence of the element means no disclosure and no mature text. (sources: https://api.microlink.io/?url=https%3A%2F%2Fstore.steampowered.com%2Fapp%2F413150%2F%3Fl%3Denglish&meta=false&data.h.selectorAll=%23game_area_content_descriptors%20%3E%20h2&data.h.attr=text&data.name.selector=%23appHubAppName&data.name.attr=text&data.cd.selectorAll=%23game_area_content_descriptors&data.cd.attr=html and https://store.steampowered.com/api/appdetails?appids=1808500&cc=us&l=english)
- app name hook: `#appHubAppName` exists on real app pages (used by the extensions as the "this is a real store page" check). (source: https://raw.githubusercontent.com/Pierre-Demessence/SteamAIGamesIndicator/main/steamAIBadge.user.js, summarized by the fetch helper)
- plain-text fetch of the app page also showed the section with the same heading and the developer text for 5072580 and for Call of Duty (1938090): `Our team uses generative AI tools to help develop some in game assets.` (source: https://store.steampowered.com/app/5072580/Courage_and_Faith_Into_the_Dark_Woods/ and https://store.steampowered.com/app/1938090/Call_of_Duty/)

detection strings the existing tools rely on, as a cross-check that the heading is literal server html:
- seeeeew fetches `https://store.steampowered.com/app/${appid}?l=english` and runs `text.match('<h2>AI Generated Content Disclosure</h2>')` on the raw response. (source: https://raw.githubusercontent.com/seeeeew/aiwarningforsteam/main/aiwarningforsteam.user.js)
- Pierre-Demessence fetches `https://store.steampowered.com/app/{appId}/?l=english`, tests the case-insensitive pattern `AI Generated Content Disclosure` against the html, and only caches a negative when the page contains `id="appHubAppName"`. (source: https://raw.githubusercontent.com/Pierre-Demessence/SteamAIGamesIndicator/main/steamAIBadge.user.js, summarized by the fetch helper)
- SoBloxsy fetches `https://store.steampowered.com/app/${appId}/` (no `l` param) and flags if the html `includes("AI Generated Content Disclosure")`; it treats fetch errors as "not flagged". (source: https://raw.githubusercontent.com/SoBloxsy/AI-Content-Hider-for-Steam/main/content.js, summarized by the fetch helper)

a bare substring match on the whole html would also fire if a developer wrote that phrase in their own description; matching `<h2>` text inside the specific container avoids that (inference, not tested).

### 1b. is the heading localized?

yes. verified by microlink with the dom selector on 5072580:
- `?l=german`: `["Offenlegung von KI-generierten Inhalten", "Beschreibung nicht jugendfreier Inhalte"]` (ai heading, then mature heading). (source: https://api.microlink.io/?url=https%3A%2F%2Fstore.steampowered.com%2Fapp%2F5072580%2F%3Fl%3Dgerman&meta=false&data.h.selectorAll=%23game_area_content_descriptors%20%3E%20h2&data.h.attr=text&data.name.selector=%23appHubAppName&data.name.attr=text)
- `?l=spanish`: ai heading `Informaci\u00f3n sobre contenido generado por IA` (written with a \u escape to keep this note ascii), mature heading `Descripci\u00f3n del contenido para adultos`. (source: https://api.microlink.io/?url=https%3A%2F%2Fstore.steampowered.com%2Fapp%2F5072580%2F%3Fl%3Dspanish&meta=false&data.h.selectorAll=%23game_area_content_descriptors%20%3E%20h2&data.h.attr=text&data.name.selector=%23appHubAppName&data.name.attr=text)
- both match the translation table shipped in seeeeew's script, which lists a heading for 30 store languages (schinese, tchinese, japanese, koreana, thai, indonesian, malay, bulgarian, czech, danish, german, english, spanish, latam, greek, french, italian, hungarian, dutch, norwegian, polish, portuguese, brazilian, romanian, russian, finnish, swedish, turkish, vietnamese, ukrainian). (source: https://raw.githubusercontent.com/seeeeew/aiwarningforsteam/main/aiwarningforsteam.user.js)

the translations are not frozen:
- Russian: Steam changed the heading; detection broke; fixed 2026-02-25 (issue 1, commit "fixed detection on Russian store pages"). the new Russian string was not stated in the issue body (unverified here; the table in the current script holds it). (sources: https://api.github.com/repos/seeeeew/aiwarningforsteam/issues/1 and https://api.github.com/repos/seeeeew/aiwarningforsteam/commits?per_page=20)
- French: on 2026-09-24 a user reported Steam changed the title from `Divulgation de contenu g\u00e9n\u00e9r\u00e9 par IA` to `Notification de contenu g\u00e9n\u00e9r\u00e9 par IA`; fixed in commit 1422d0851c81fd85950e435d31e399dc21b0c045 (version 1.1.1, announced as 1.1.2 on 2026-09-25). (sources: https://api.github.com/repos/seeeeew/aiwarningforsteam/issues/13/comments and https://api.github.com/repos/seeeeew/aiwarningforsteam/commits/1422d0851c81fd85950e435d31e399dc21b0c045)
- Malay was missing until 2026-06-13 (issue 5). issue 4 (open) proposes a script that checks whether headings changed in any language. (source: https://api.github.com/repos/seeeeew/aiwarningforsteam/issues?state=all&per_page=30)

consequence: only the english heading (fetched with `?l=english`) is a stable key so far; any localized table needs a refresh mechanism, and a localized-dom check should fall back to an english fetch when the heading is unknown.

### 1c. age gates, login walls, redirects that affect fetching

- app 5072580 and 1808500: server html returned directly, no gate (microlink, `prerender=false`, no cookies). (sources: microlink urls above)
- Call of Duty (1938090; search row shows `data-ds-descids` `[2,5]`): the same cookie-less microlink fetch (both `?l=german` and `?l=english`) ended at `https://store.steampowered.com/agecheck/app/1938090/` with title "Call of Duty" and no `#game_area_content_descriptors`. the agecheck page itself returned HTTP 200 and its dom ids were `valve-ssr-data`, `StoreTemplate`, `searchSuggestions_...`, `footer` (a react shell; none of the old age form ids). by contrast, the plain-text fetch tool got the full store page for the same app, so the gate depends on the client (cookies, location). (sources: https://api.microlink.io/?url=https%3A%2F%2Fstore.steampowered.com%2Fapp%2F1938090%2F%3Fl%3Denglish&meta=false&prerender=false&data.h.selectorAll=%23game_area_content_descriptors%20%3E%20h2&data.h.attr=text&data.name.selector=%23appHubAppName&data.name.attr=text&data.form.selector=%23agegate_box&data.form.attr=html&data.title.selector=title&data.title.attr=text , https://api.microlink.io/?url=https%3A%2F%2Fstore.steampowered.com%2Fagecheck%2Fapp%2F1938090%2F&meta=false&prerender=false&data.ids.selectorAll=%5Bid%5D&data.ids.attr=id , https://store.steampowered.com/app/1938090/Call_of_Duty/)
- adult-only app HuniePop (339800): both the fetch tool and microlink landed on `https://store.steampowered.com/login/?redir=https%3A%2F%2Fstore.steampowered.com%2Fagecheck%2Fapp%2F339800%2F` (title "Sign In"). (sources: https://store.steampowered.com/app/339800/HuniePop/ and https://api.microlink.io/?url=https%3A%2F%2Fstore.steampowered.com%2Fapp%2F339800%2F&meta=false&prerender=false&data.title.selector=title&data.title.attr=text&data.h.selectorAll=%23game_area_content_descriptors%20%3E%20h2&data.h.attr=text&data.ageform.selector=%23ageYear&data.ageform.attr=html)
- nonexistent appid 99999999: microlink reported a 302 and a final url of `https://store.steampowered.com/` (title "Welcome to Steam"), so a delisted or invalid app also yields a 200 html page with no `#appHubAppName`. (source: https://api.microlink.io/?url=https%3A%2F%2Fstore.steampowered.com%2Fapp%2F99999999%2F&meta=false&prerender=false&data.title.selector=title&data.title.attr=text&data.name.selector=%23appHubAppName&data.name.attr=text)
- practical rule: `fetch()` follows redirects silently with a 200 at the end, so check `response.url` for `/agecheck/` or `/login/` and/or the presence of `id="appHubAppName"`; Pierre-Demessence does the latter so that "age gates, login walls, or error pages" are not cached as negatives. an extension fetching from the user's own logged-in browser sends the user's cookies and sees the user's view; a background fetch with `credentials: "omit"` does not (inference; not tested here). i did not research ways to spoof age cookies and the note does not cover them.
- region: i did not find or test a store-page region redirect beyond `StoreItem.unvailable_for_country_restriction` (a bool in the GetItems proto, field 5; spelling as in the proto). `cc` only influenced price in the calls i made. (source for the proto field: https://raw.githubusercontent.com/SteamDatabase/Protobufs/master/webui/common.proto, offset 200000 via the fetch helper). unverified for html pages.
- whether a fetch with `?l=english` writes a language cookie that flips the user's own store language is unverified. forum posts say a `?l=` link tends to "stick" for the user, but nothing i fetched confirmed it for a background `fetch`. (source: web search results, e.g. https://steamcommunity.com/discussions/forum/1/1729828401709606496)

- request: `https://store.steampowered.com/api/appdetails?appids=5072580` (also with `cc=us&l=english`). response is keyed by the appid string with `success` and `data`. (source: https://store.steampowered.com/api/appdetails?appids=5072580&cc=us&l=english)
- `data` keys for 5072580 (31 listed): `type, name, steam_appid, required_age, is_free, dlc, detailed_description, about_the_game, short_description, supported_languages, header_image, capsule_image, capsule_imagev5, website, pc_requirements, mac_requirements, linux_requirements, developers, publishers, demos, package_groups, platforms, categories, genres, screenshots, movies, release_date, support_info, background, background_raw, content_descriptors, ratings`. no key named for ai, generative or disclosure. (source: same url)
- `content_descriptors.ids` is `[5]`; `content_descriptors.notes` starts `The game contains dark fantasy violence, combat involving weapons and supernatural creatures, descrip...` and is the mature-content free text, not the ai text. (source: same url)
- the strings `Generated Content Disclosure` and `Generative AI is used in both pre-generated` do not occur anywhere in the 5072580 response; for ARC Raiders neither `Generated Content Disclosure` nor `AI-based tools to assist with content creation` occurs (its `content_descriptors` is `ids: []`, `notes: null`). so appdetails cannot be used for detection. the only ai wording is incidental, e.g. `short_description` "AI-generated narration reacts to your decisions" and a `pc_requirements` note about live ai features. (sources: https://store.steampowered.com/api/appdetails?appids=5072580&cc=us&l=english and https://store.steampowered.com/api/appdetails?appids=1808500&cc=us&l=english)
- tooling note: the fetch helper would not print the full json verbatim, so key lists came from its enumeration; two separate fetches of the 5072580 response gave the same key list and `ids`.

### 2b. `IStoreBrowseService/GetItems` (api.steampowered.com)

this is the endpoint that does expose the disclosure.

request shape that worked with no api key (decoded `input_json`):

```
{"ids":[{"appid":5072580}],"context":{"language":"english","country_code":"US"},"data_request":{"include_extra_details":true}}
```

url: `https://api.steampowered.com/IStoreBrowseService/GetItems/v1?input_json=<urlencoded json above>` (source: https://api.steampowered.com/IStoreBrowseService/GetItems/v1?input_json=%7B%22ids%22%3A%5B%7B%22appid%22%3A5072580%7D%5D%2C%22context%22%3A%7B%22language%22%3A%22english%22%2C%22country_code%22%3A%22US%22%7D%2C%22data_request%22%3A%7B%22include_extra_details%22%3Atrue%7D%7D)

response layout: `response.store_items[]`, each with `item_type, id, success, visible, name, store_url_path, store_url_slug, appid, type, related_items, content_descriptorids, categories, is_coming_soon, extra_details` when only `include_extra_details` is set. (source: same url)

the ai fields, in `store_items[].extra_details`:
- `content_survey_ai_notes` (string): the developer's free text. for 5072580 it begins "Generative AI is used in both pre-generated and live-generated content." and continues with the artwork, music, sound effects and live narrative text description, i.e. the same text shown in the page's `<i>`. for Call of Duty (1938090) the whole value was `Our team uses generative AI tools to help develop some in game assets.` (matching the page text); for ARC Raiders (1808500) it begins "During the development process, we may use procedural- and AI-based tools to assist with content cre" (matching the page's `<i>` start). absent for Stardew Valley (413150). (sources: https://api.steampowered.com/IStoreBrowseService/GetItems/v1?input_json=%7B%22ids%22%3A%5B%7B%22appid%22%3A5072580%7D%2C%7B%22appid%22%3A1808500%7D%2C%7B%22appid%22%3A1938090%7D%2C%7B%22appid%22%3A413150%7D%5D%2C%22context%22%3A%7B%22language%22%3A%22english%22%2C%22country_code%22%3A%22US%22%7D%2C%22data_request%22%3A%7B%22include_extra_details%22%3Atrue%7D%7D and https://api.steampowered.com/IStoreBrowseService/GetItems/v1?input_json=%7B%22ids%22%3A%5B%7B%22appid%22%3A413150%7D%5D%2C%22context%22%3A%7B%22language%22%3A%22english%22%2C%22country_code%22%3A%22US%22%7D%2C%22data_request%22%3A%7B%22include_extra_details%22%3Atrue%7D%7D)
- `ai_generation_service` (object with `name`, `url`): seen only on 5072580 as `{"name":"OpenAI API","url":"https://openai.com/api/"}`; absent for 1808500, 1938090 and 413150. it appears to be a live-generation service declaration; its meaning and when it is shown on the page are unverified (the sample page did not render it in the block structure i saw). (source: the 4-app GetItems url above, plus a separate single-app fetch of 5072580 that listed `.ai_generation_service.name` and `.ai_generation_service.url`)
- `content_survey_notes` (string) is the mature-content free text, separate from the ai notes. (same urls)
- other keys seen under `extra_details`: `vetted, controller_wizard_complete, interactive_elements, links_and_info, system_requirements` (5072580); the set varies per app (ARC Raiders also had `steam_award, anticheat, eula, section, legal_notice_bbcode, press_review, partner_awards_bbcode`). there is no boolean or enum for "pre-generated" vs "live-generated"; only the free text and the optional service object. (same 4-app url)
- protobuf confirmation: `StoreBrowseItemDataRequest` has `optional bool include_extra_details = 18;` and `StoreItem_ExtraDetails` declares `optional .StoreItem_ExtraDetails_AIGeneratedContentService ai_generation_service = 11;` and `optional string content_survey_ai_notes = 17;`; the service message has `name = 1` and `url = 2`. (source: https://raw.githubusercontent.com/SteamDatabase/Protobufs/master/webui/common.proto, offset 200000, via the fetch helper)
- full list of request flags in `StoreBrowseItemDataRequest`: `include_assets, include_release, include_platforms, include_all_purchase_options, include_screenshots, include_trailers, include_ratings, include_tag_count (int32), include_reviews, include_basic_info, include_supported_languages, include_full_description, include_included_items, included_item_data_request, include_assets_without_overrides, apply_user_filters, include_links, include_extra_details, include_best_purchase_option, include_optin_registration_tags`. (same proto source)
- batching: four appids in one request worked. the maximum ids per call is unverified.

what the other flags return for 5072580 (no ai marker anywhere in them):
- with `include_basic_info`, `include_tag_count`, `include_ratings`: `content_descriptorids: [5]`, `categories.supported_player_categoryids [2]`, `categories.feature_categoryids [35, 62]`, `basic_info.short_description` (the "AI-generated narration reacts to your decisions" text is just the marketing blurb), `basic_info.developers/publishers[].name`, `tags[]` as `{tagid, weight}` (20 entries when `include_tag_count` is 20; first tagids 10695, 11014, 6426, 4325, 1742), and `game_rating.content_survey_notes` (the mature text). (source: https://api.steampowered.com/IStoreBrowseService/GetItems/v1?input_json=%7B%22ids%22%3A%5B%7B%22appid%22%3A5072580%7D%5D%2C%22context%22%3A%7B%22language%22%3A%22english%22%2C%22country_code%22%3A%22US%22%7D%2C%22data_request%22%3A%7B%22include_basic_info%22%3Atrue%2C%22include_tag_count%22%3A20%2C%22include_ratings%22%3Atrue%7D%7D)
- with the broad flag set (assets, release, platforms, purchase options, screenshots, trailers, ratings, tags, reviews, basic info, languages, full description, links): additionally `tagids`, `reviews.summary_filtered`, `assets`, `release`, `platforms`, `screenshots`, `trailers`, `supported_languages`, `full_description_bbcode`. `game_rating` held only `content_survey_notes` there. the string `AI Generated Content Disclosure` appears nowhere in that response and `full_description_bbcode` is the "About This Game" bbcode only. (source: the broad-flag GetItems call, input_json with all `include_*` flags true and `include_tag_count` 5, same endpoint)
- `StoreGameRating` in the proto has `type, rating, descriptors, interactive_elements, agency, banned, esrb_online_*, survey_interactive_elements, required_age, use_age_gate, descriptor_images, content_survey_notes (13), image_url, image_target`; no ai field. (source: proto above)
- stability: `GetItems` is a Valve web ui endpoint described only by reverse engineered protobufs (SteamDatabase/Protobufs); i found no Valve documentation for `include_extra_details`. steam could rename or gate it. (the xPaw api index page did not list method details in the fetched content, https://steamapi.xpaw.me/)

### 2c. content descriptor ids and user tags

what a per-app request looks like (for the extension):
1. preferred: batch `GET https://api.steampowered.com/IStoreBrowseService/GetItems/v1?input_json={"ids":[{"appid":A},{"appid":B},...],"context":{"language":"english","country_code":"US"},"data_request":{"include_extra_details":true}}`; disclosed iff `store_items[i].extra_details.content_survey_ai_notes` is a non-empty string. one call can cover a whole search page or wishlist (batch ceiling unverified). no age gate or cookie dependence was seen in the json route (4 apps incl. Call of Duty returned data from the fetch tool; a cookie-less check of an age-gated app through this endpoint was not run).
2. fallback: `GET https://store.steampowered.com/app/<appid>/?l=english`, check the final url and `id="appHubAppName"`, then look for `<h2>AI Generated Content Disclosure</h2>` inside `#game_area_content_descriptors`, and read the free text from the `<i>` of the second `<p>`.
3. on the app page itself the block is already in the dom; query `.game_page_autocollapse > #game_area_content_descriptors > h2` with all headings known, and fall back to option 1 or 2 if no heading matches but the page may still disclose.

## main-thread verification (2026-10-20, built-in browser, no steam login, no api key)
- `GetItems` with `include_extra_details: true` for 5072580 and 413150 returned `extra_details.content_survey_ai_notes` (the full english disclosure text) and `ai_generation_service` `{"name":"OpenAI API","url":"https://openai.com/api/"}` for 5072580. both keys were absent for Stardew Valley 413150, whose `extra_details` keys were `vetted, press_review, partner_awards_bbcode, links_and_info, points_shop_eligible, metacritic, system_requirements`.
- from a page on `https://store.steampowered.com`, a plain `fetch()` to `api.steampowered.com/IStoreBrowseService/GetItems/v1` returned 200 with a readable body, so cors permits the store origin. `access-control-allow-origin` cannot be read from js, so whether it is a wildcard or echoes the origin is unknown.
- batch ceiling: the 50 rows of `store.steampowered.com/search/?term=roguelike` (ids from `#search_resultsRows a[data-ds-appid]`) went out in one request (encoded `input_json` about 1.7 KB) and returned 50 items in about 1.3 s, 10 of them with `content_survey_ai_notes`. larger batches were not tried.
- dom on the sample app page (`?l=english`): exactly two `#game_area_content_descriptors.game_area_description` elements, both children of `.game_page_autocollapse`. the first has `<h2>AI Generated Content Disclosure</h2>` and the second has `<h2>Mature Content Description</h2>`. this confirms the duplicate id.
- a same-origin `fetch('/app/413150/?l=english')` from the search page returned 200, contained `appHubAppName`, and did not contain the ai heading.

## caveats and version notes
- all html structure came through a third-party headless fetch api plus a summarizing model; no byte-exact copy of the page source was read. snippets above are faithful to what was returned, but whitespace, attribute order and any extra classes could differ. re-verify with devtools before shipping selectors.
- the json route result for `ai_generation_service` is based on one app. do not depend on it for detection.
- `content_survey_ai_notes` text is the english-context value; whether it varies with `context.language` is unverified.
- whether `content_survey_ai_notes` can exist on an app whose page does not render the section (for example not yet approved) is unverified. the sample app was "coming soon" and showed both.
- policy context: Valve rewrote its disclosure rules around 2026-01-17 (what must be disclosed; the article does not say the page section changed), and the Steamworks Content Survey has a "Generative Artificial Intelligence Content" section with pre-generated and live-generated parts and a guardrails question; that doc page does not say where the text is shown or whether an api exposes it. (sources: https://www.videogameschronicle.com/news/valve-has-significantly-rewritten-steams-rules-for-how-developers-much-disclose-ai-use and https://partner.steamgames.com/doc/gettingstarted/contentsurvey)
- false positives are a policy problem, not a markup one: a publisher's ai upscaling disclosure triggers the section (issue 12). (source: issues api url above)
- the steam announcement "AI Content on Steam" (https://steamcommunity.com/groups/steamworks/announcements/detail/3862463747997849619) returned only navigation text, so the original 2024 statement was not read.
- the web search tool declined to explain age-cookie workarounds; none were researched or recorded here.
- CORS and MV3 behavior (service worker with host permissions vs content script) for `api.steampowered.com` was not tested.
