## 1. Recommended design A: tabs, left rail on wide screens, wrapping row when narrow
### 1.1 Structure
- New dep layout: "tabs" | "list" in SettingsFormDeps (page: tabs; dialog: tabs with popup density, colors true; toolbar popup: list). context keeps density and page-only pieces. One code path: kindCard(kind) becomes kindBody(kind); tabs layout puts it in a tabpanel, list layout uses only its master switch row.
- TabId = "general" | KindId, built from kindsInOrder() (slice 1: KINDS; slice 2: stored order). New kinds get a tab with no form edit.
- DOM: header, load error above everything, div[role=tablist][aria-label=options_tabs_label], panels (all rendered at mount; inactive carry hidden so sync() and settingControls work unchanged).
- General panel: h2 General; Language (page only); color help once (id referenced by aria-describedby of every color input); Ignored for all tags (three lists, scope all); Backup (deps.backup); Privacy (page).
- Kind panel: h2 = Steam heading; master switch; options (facets, badge, banner, color, filter); "Ignored for this tag": three lists for scope = kind, non-empty only (all empty: one line options_allow_empty with action banner_ignore_kind); the All-tags note when count > 0: options_allow_all_note_one/_other + button options_allow_all_show "Show in General" (data-sar-tab="general", a button not a hash link, because in the dialog a hash would change the store URL). Per-field color help becomes options_color_help_short (amends decision 49 help placement).
- Tab element: button[role=tab][id][aria-controls][aria-selected][tabindex]; span.sar-tab-label[aria-hidden] = chip word (slice 3: custom text); span.sar-vh = kind_chip_name minus the visible part (helper exported from kind-details.ts or badge.ts, no new key); span.sar-tab-state = options_state_on/off updated in sync(). General tab: text only. Panel: div[role=tabpanel][id][aria-labelledby], no tabindex.
### 1.2 Keyboard and screen reader
- Automatic activation; roving tabindex; ArrowRight/Down next, ArrowLeft/Up previous, wrapping; Home/End; both axes (no aria-orientation). One delegated keydown on root, filtered to [role=tab]; click selects via the existing click handler. SR: "KLAC: Uses Kernel Level Anti-Cheat On, tab, selected, 2 of 12". Selection writes v2:ui through the serial (skips unchanged).
### 1.3 Layout and CSS (settings.css + tokens)
- Tokens --sar-options-max-width-tabs: 880px, --sar-tabs-rail-width: 200px. min-width 800px: grid rail + panels, vertical tablist, sticky rail. Narrower: flex-wrap tabs (about 3 rows at 360-400px). Selected: 2px inline-start bar (rail) or block-end bar (row) in --sar-accent-400 plus strong text. Forced colors: selected tab border Highlight plus CanvasText outline; state text stays words. Focus ring list gains [role=tab]; no transitions. Remove details/summary rules (about 1.2 KB). Dialog: inline-size min(760px, calc(100vw - var(--sar-space-6))).
### 1.4 Popup (layout list)
- Header: icon, name, version, gear at inline end: a.sar-gear[href=allSettingsUrl][target=_blank][rel=noopener][aria-label=options_all_settings] with an original inline SVG (circle with dashed thick stroke + inner circle, under 300 B), sticky. No ignore lists, no footer link; footer keeps options_privacy_no_reports and options_unaffiliated_short. Click on the name opens that tab in a new tab (popup closes); switch toggles in place. Supersedes decision 48 everywhere and decision 31's empty-list rule. Enhancement (open question 8): runtime.openOptionsPage() plus a v2:ui write of the requested tab (about 25 lines in platform code).
### 1.5 Hash and memory

## Maintainer feedback after the mockups (2026-10-26)
- Dialog width 760px with the rail: approved ("ublock origin, 1password and gg.deals use a similar one").
- Popup: option C confirmed.
- Order control: DRAG AND DROP instead of Move up/Move down buttons (design: drag handle per row, pointer events, no library; keep a keyboard alternative on the handle (Space to pick up, arrow keys to move, Space or Enter to drop, Escape to cancel) with a live-region announcement; consider WCAG 2.5.7 single-pointer alternative (a plain drag is a dragging movement: decide whether a small non-text up/down affordance is kept for pointer users who cannot drag) and touch support (HTML5 DnD does not work on touch and is flaky in Firefox for Android: prefer pointer events)). Bytes estimate to redo (pointer-event sortable about 2 to 3 KB).
- Tabs sorted ALPHABETICALLY by their displayed label (General first, then A to Z in the UI locale with localeCompare; custom chip text changes the sort). The tag order setting therefore no longer drives the tabs or the popup: it drives chips, the tag section, hover card, banner entries and package summary only. Popup rows: alphabetical too (maintainer confirmed tabs; popup follow tabs unless told otherwise).
- 'Stop ignoring' buttons are too heavy: restyle as the quiet link-like text button used by Reset (same design language), in the settings lists (page, dialog, popup n/a).
- The small icon beside the popup header in the mock is the SETTINGS GEAR (a quick placeholder I drew; final icon is an original gear, not a dashed ring).
- Family Sharing wording (separate branch fix/family-sharing-wording): default chip for the unavailable value 'No Family Sharing' (es 'Sin prestamo familiar'), card value line 'Family Sharing is not supported for this game', and the source line 'According to Valve' becomes 'According to the features Steam lists for this game' for this kind. Requires amending rule 4 and ADR 0016 and a narrow exception in the catalog guard.
